# AMCN 技術台帳（アーキテクチャと導入技術の一覧）

AMCN（アムチン / AI Markdown Chat Note）にこれまで導入した技術と仕組みをまとめた台帳です。各項目には、それが実際にどのソースファイルに置かれているかを併記しています。

記載内容は 2026-09-01 時点のソースコードに基づきます。行数・件数は実測値です。

| 指標 | 値 |
| --- | --- |
| プラットフォーム | 2（PC / モバイル） |
| IPCチャンネル | 29系統 |
| コード行数 | 約9,800行 |
| ノート件数 | 4,200件超 |

---

## 1. 全体構成

AMCNの中心には**アプリのソースとは別のGitリポジトリ**があり、そこにノートの実体（`.md`）が置かれています。PC版とモバイル版は同じリポジトリを見ますが、到達手段がまったく異なるのが構造上の要点です。

```
  ┌──────────────────┐        ┌────────────────────────┐        ┌──────────────────┐
  │ PC — Electron    │        │ GIT REPOSITORY         │        │ MOBILE — PWA     │
  │ デスクトップ版    │        │ ノートデータ            │        │ モバイル版        │
  │                  │  push  │                        │ GET raw│                  │
  │ simple-git で    │ ─────> │ notes/YYYY-MM/*.md     │ <───── │ GitHub REST API  │
  │ クローン操作      │        │ private/*.md（暗号化）  │        │ 直接              │
  │ Node fs で       │ <───── │ moc/_All_Notes_MOC.md  │ ─────> │ ローカルクローン  │
  │ 直接読み書き      │  pull  │ _index.json            │  PUT   │ なし              │
  │ _index.json の   │--rebase│ _custom_prompts.json   │contents│ _index.json の   │
  │ 書き手            │        │ _master_tags.json      │        │ 読み手            │
  └────────┬─────────┘        └────────────────────────┘        └─────────┬────────┘
           │                   ┌────────────────────────┐                 │
           └─────────────────> │ GOOGLE GEMINI API      │ <───────────────┘
                               │ ストリーミング + 単発生成 │
                               └────────────────────────┘
```

PC版はローカルクローンをsimple-gitで操作し、モバイル版はクローンを持たずGitHub REST APIを直接叩きます。両者はGemini APIをそれぞれ直接呼び、**AI処理のためのサーバーは存在しません**。

## 3. 主要な仕組み

### 3-1. AIチャットと自動ノート化

**対象**: PC + モバイル / `src/renderer/src/lib/gemini.ts`, `mobile/src/lib/gemini.ts`

Gemini APIとの会話がそのままノートに追記されていき、ノートが「育つ」設計です。ノートを開いていない状態で会話すると、AIにタイトルを生成させて新規ノートを作り、作成日時の年月フォルダへ自動で振り分けます。

* **6つのチャットモード** — 深掘り / Markdown構造化 / 長文解説 / プロンプト生成 / 長文ドキュメント解析 / MOC参照。それぞれ専用のシステムプロンプトを持つ
* **モデルのフォールバック連鎖** — `MODEL_CANDIDATES` で候補を順に試す。単発生成（タイトル・タグ・MOC）も `callGenerateContent` に集約し、片方が503を返しても機能が無反応にならないようにした
* **MOC参照モード** — 質問文からキーワードを切り出し、ファイル名一致10点・タグ一致5点でノートを採点、上位50件だけを文脈として送る
* **カスタムプロンプト** — PC・モバイル間でID単位の和集合マージ。`isPrivate` フラグ付きのものはプライベートモード時のみ表示
* **混雑時の自動リトライ** — `chatStream` は503/429時、モデルを切り替える前に同一モデルへ2秒・5秒間隔で再試行する。それでも失敗した場合はチャット欄にエラーと「再試行」ボタンを表示し、ユーザーメッセージを重複させずに同一リクエストを再送できる（`runChatRequest` / `retryLastChat`、[App.tsx](../src/renderer/src/App.tsx)）
* **ストリーミング表示の簡素化** — 受信中はMarkdown解析をせず素のテキスト（`white-space: pre-wrap`）で表示し、回答完了後にのみ整形表示へ切り替える。文章量に比例して重くなる逐次再パースを避けるため

### 3-2. タグ正規化パイプライン

**対象**: PC + モバイル / `src/renderer/src/App.tsx`, `mobile/src/lib/notes.ts`

4,400件のノートに `タグ:` / `tags:` / `タグ：` という表記揺れ、`#` の有無、複数タグ行、AIが出力したブラケットや日付のゴミタグが混在していたため、書き込み側を一本化しました。

* `sanitizeTag()` — 前後の記号除去、`[[x]]` の展開、日付・1文字・空文字の棄却
* `sanitizeTags()` — 大文字小文字を無視して重複を排除し、**既存のマスタータグに同義のものがあればその表記へ寄せる**。無ければ新規としてタグ一覧へ追加
* `applyTagsToContent()` — 既存のタグ行を全削除したうえで、末尾に `タグ: A, B, C` を1行だけ付ける。タグが空なら行自体を書かない
* 手動追加・自動保存・AIタグ生成の3経路すべてがこの関数を通る

### 3-3. WikiLinkとグラフビュー

**対象**: PC / `src/renderer/src/GraphView.tsx`

`[[ノート名]]` 記法でノート同士を繋ぎ、その関係をグラフとして可視化します。完全一致から前方一致まで5段階のフォールバックでリンク先を解決し、見つからなければ新規作成を提案します。

* **2Dはsigma.js（WebGL）、3Dはthree.js**。設定と座標は次元ごとに分離して保存
* **グリッド空間分割** — 斥力計算をセルサイズ＝カットオフ半径の一様グリッドで近似し、総当たりのO(N²)を回避
* **事前計算してから描画** — 毎フレームWebGLを再描画しながら収束させるのをやめ、レイアウトを同期的に確定させてからSigmaを生成。移動量が閾値を下回れば途中で打ち切る
* **グラフの二層化** — 構造（ノード・エッジ）と装飾（色・サイズ）のuseMemoを分離し、色や検索語の変更でグラフ全体を作り直さない
* 算出した座標は全件キャッシュするため、2回目以降のオープンは即座に表示される

### 3-4. 暗号化保管庫

**対象**: PC + モバイル / `src/main/cryptoVault.js`, `mobile/src/lib/cryptoVault.ts`

`private/` 配下のノートを **AES-256-GCM + PBKDF2-SHA256（20万回反復）** で暗号化します。PC版はNode標準 `crypto`、モバイル版はWeb Crypto APIという別実装ですが、保存フォーマットは完全互換です。

* ヘッダ行＋`salt` / `iv` / `tag` / `data` のBase64行という自前のテキスト形式。Web Cryptoは認証タグを暗号文末尾に含めるため、書き出し時に分離し読み込み時に再結合して相互運用している
* **ファイル名の匿名化** — `private/` の新規ノートはタイムスタンプIDで保存し、表示名は暗号化した `_names.enc` にマッピングを持つ。GitHub上ではファイル名からも内容が推測できない
* `_vault.json` に検証用トークンを置き、パスワードの正誤だけを判定できるようにしている
* パスワードはメモリ上にのみ保持し、既定15分で自動ロック

### 3-5. Git同期（PC側）

**対象**: PC / `src/main/main.js`

自動同期をやめ、「コミット＆プッシュ」「プル」の2ボタンによる明示的な操作に整理しました。ファイル監視・30秒デバウンスの自動コミット・5分ごとの自動プルは撤去しています。

* `gitSyncQueue` — Promiseチェーンで全git操作を直列化し、`index.lock` の衝突を防ぐ
* `ensureOnMainBranch()` — ローカルのチェックアウト状態に関わらず必ず `main` で操作する。PC側が `master` へ分岐して履歴が二重化した事故への対策
* `pull --rebase --autostash` — アプリ自身が再生成した `_index.json` の差分でプルが止まらないように
* `.gitattributes` に `moc/_All_Notes_MOC.md merge=union` を自動投入し、追記型ファイルの競合を行単位マージで回避
* 終了時はレンダラ側の確認モーダルと連動し、未プッシュ分を処理してから閉じる

### 3-6. GitHub直接アクセス（モバイル側）

**対象**: モバイル / `mobile/src/lib/githubSync.ts`

端末にリポジトリをクローンせず、GitHub REST Contents APIで必要なファイルだけを都度取得・更新します。ノート本文は端末に永続化されず、メモリとGitHubの間だけを往復します。

* **rawメディアタイプの併用** — 通常のContents APIは1MBを超えると `content` が空で返るため、`Accept: application/vnd.github.raw` で取得する経路を用意した
* `fetchJsonForWrite()` — 書き込み時は通常取得を試し、サイズ超過で空だった場合のみraw取得へフォールバックしてshaを確保する
* ノート一覧・追加・削除はすべて**フルパス**で突き合わせる（同名ファイルが別フォルダにある場合の取り違え防止）
* リモート取得結果はローカル状態と和集合でマージし、直前に作ったノートがインデックス反映前に消えないようにしている

### 3-7. 共有メタデータインデックス

**対象**: PC + モバイル / `_index.json`

PC版が書き手、モバイル版が読み手となる共有インデックスです。モバイル版はこれを1回読むだけで全ノートのパスと日時を得られるため、ファイルを個別に取得する必要がありません。

* 当初は `name` / `tags` / `isMoc` などを含む整形済みJSONで1.27MBあり、GitHubの1MB制限に抵触していた
* `{path, updatedAt}` のみのスリム形式＋インデントなしの圧縮出力に変更し、約400KB台へ縮小
* ノートの日時は **本文の作成日時行 → フロントマターの `date:` → gitの追加日時 → ファイルのmtime** の順で解決する。mtimeはgit pullで一斉に書き換わるため最後の手段に置いている

## 4. パフォーマンス設計

4,000件規模で常用するため、性質の異なる3層のキャッシュを使い分けています。何を、どこに、いつまで持つかを層ごとに変えているのが要点です。

| キャッシュ | 内容 | 寿命 |
| --- | --- | --- |
| `metadata_cache.json` | タグ・WikiLink・空ノート判定・作成日時をディスクに保存。スキーマ変更時は `_version` を上げて全件再構築 | ディスク / mtime連動 |
| `cache._gitDates` | gitの追加日時のみを別枠で永続化。既存ファイルの追加日時は変わらないためmtime非連動。機密性もないのでプライベートノートも対象 | ディスク / 永続 |
| `privateMetaCache` | 暗号化ノートの復号結果（表示名・タグ・作成日時）をプロセスメモリにのみ保持。ロック・自動ロック時に破棄 | メモリ / ロックで破棄 |

これに加えて、描画側にも次の対策を入れています。

| 対策 | 内容 | 対象 |
| --- | --- | --- |
| `NotePreview`（React.memo） | チャット入力の1文字ごとにApp全体が再レンダリングされ、そのたびreact-markdownがノート全文を再パースしていた。プレビューを切り出してmemo化し、コールバックはref経由の安定参照にした | PC |
| `NoteSidebarList`（React.memo） | サイドバーのノート一覧（4,000件超）がmemo化されておらず、チャットのストリーミング更新などApp全体の再レンダリングのたびに全件作り直されていた。切り出してmemo化した | PC |
| ストリーミングのチャンク間引き | Geminiからのトークンを都度setStateすると再レンダリングが多発するため、ref上に貯めて70msごとにまとめて反映するようにした | PC |
| `limitConcurrent(tasks, 50)` | ノートスキャンのファイル読み込みを50並列に制限。全件を一斉に開いてファイルディスクリプタを枯渇させない | PC |
| `useVirtualizer` | ノート一覧を仮想化し、表示範囲の行だけをDOMに載せる | モバイル |

## 5. 落とし穴と対策

実際に起きた不具合と、その根本原因・恒久対策の記録です。いずれも実データに対して検証したうえで修正しています。

### 5-1. タグがノート上部に表示されない

* **原因**: タグ抽出が `split('\n')` のあと `(.+)$` で照合していたため、CRLF改行だと行末に残る `\r` を `.` が消費できずマッチに失敗。加えて走査範囲が先頭2万文字までで、タグ行を末尾に統一した結果、長文ノートで範囲外に落ちていた。
* **対策**: 改行に依存しない `[^\r\n]*` の全体正規表現へ置換し、末尾2000文字も走査対象に追加。実データ4,207件すべてで抽出成功を確認。

### 5-2. モバイルでノートの日付がすべて同じ時刻になる

* **原因**: `_index.json` が1.27MBに肥大し、GitHub Contents APIが1MB超で `content` を空にして返していた。パースに失敗し、全ノートの日時が「取得した瞬間の現在時刻」にフォールバックしていた。
* **対策**: インデックスを `{path, updatedAt}` のみの圧縮JSONに変更（約400KB台）。あわせて読み取り経路をrawメディアタイプへ移し、二重に防いだ。

### 5-3. PC版の動作が重い

* **原因**: ノート一覧の取得はほぼ全操作で走るが、そのたびに `private/` の各ノートをPBKDF2 20万回反復でフル復号し直していた。さらに以前は、日時解決のための `git log` も毎回実行していた。
* **対策**: git追加日時を永続キャッシュ化し、復号結果はmtime連動のメモリキャッシュに載せた。ロック時に破棄するため機密性は維持される。

### 5-4. ノートが空になって消える

* **原因**: モバイルでノートを開くとき、表示を即座に空にしてから本文を非同期取得していた。取得が自動保存のデバウンス（1.2秒）より遅いと、空の内容でGitHub側を上書きしてしまう。
* **対策**: 自動保存の先頭に空内容ガードを追加。過去に空化した8件はgit履歴から特定し、まだ空だった3件を親コミットから復元した。

### 5-5. PCとモバイルで履歴が二重化する

* **原因**: PC版がローカルのチェックアウト状態に従って `master` を押していた一方、モバイル版はREST API経由で常にリポジトリ既定の `main` に書いていた。
* **対策**: 両ブランチをマージして `master` を廃止し、PC側に `ensureOnMainBranch()` を追加して常に `main` で操作するようにした。

### 5-6. Windows・OneDrive環境固有の詰まり

* **原因**: OneDrive配下のビルド出力を別プロセスが掴んでおり `app.asar` を置換できなかった（Restart Manager APIで特定）。また、モバイルで作った長いファイル名がWindowsのパス長制限に触れ、PC側のプルを失敗させていた。
* **対策**: ビルド出力先をOneDrive外の `AppData/Local/AiChatBuild` へ移動。ファイル名は両プラットフォームとも50文字で切り詰めるようにした。

## 6. ビルドとデプロイ

PC版は署名なしのディレクトリ出力＋アイコン後埋め込み、モバイル版はブランチを差し替えてVercelへ送る構成です。

| コマンド / 場所 | 内容 |
| --- | --- |
| `npm run dist` | PC版のビルド。`tsc && vite build` → electron-builder（`--win dir`、署名探索は無効化）→ `scripts/embed-icon.mjs` でrceditによりアイコンを埋め込む |
| `AppData/Local/AiChatBuild` | ビルド成果物の出力先。OneDriveの同期対象外に置くことでファイルロックを避けている |
| `deploy-mobile.ps1` | 作業中の変更をstashし、配信用ブランチへ `mobile/` だけを `git archive` で展開・コミットしてVercel用リモートへプッシュ。元のブランチへ戻してstashを復帰する |
| `feature/v3` | 開発ブランチ。アプリのソースリポジトリはノートデータのリポジトリとは完全に別で、混同しないよう分離している |
